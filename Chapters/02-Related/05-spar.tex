\label{sec:spar}
\begin{itemize}
    \item An answer to the impractical instantiation of \gls{niar} (uses established FHE assumptions and operations)
    \item Sorting random values = shuffling, but shuffling a large array is slow
    \item sPAR uses the sorting from \cite{park:sortinghat:2022} to sort the values into $\eta$ buckets. Each of the buckets are sorted relatively quickly. % TODO: cite source for sorting speed! 
    \item Choice-of-three trick briefly explained
    \item Anonymous router primitive
    \item Trades away non-interactivity
\end{itemize}

\subsubsection{Setup}
\begin{itemize}
    \item Parties agree on parameters (or assumed this is done before even starting the setup phase!)
    \item One-time multi-party key generation as in \autoref{sec:mpfhe}: each client samples $s_i$ and publishes a public share; shares aggregate into a joint public key $\hat{pk}$ whose secret $s = \sum_i s_i$ is never reconstructed
    \item Maybe: The permutation is \emph{not} an input to setup (contrast \gls{niar}); freshness per round comes from client randomness in the online phase % Might fit better in introduction 
\end{itemize}

\subsubsection{Client: Encryption}
\begin{itemize}
    \item Client $u_i$ encrypts its message under the joint key: $c_i = \rlwe(m_i)$
    \item Picks three bucket indices $a_1, a_2, a_3 \overset{\$}{\leftarrow} [0, \eta)$, independently and uniformly
    \item Encrypts each of the $\log\eta$ bits of each $a_w$ individually (\gls{rlwe} ciphertexts)
    \item Sends $c_i$ and the $3\log\eta$ bit encryptions to the server over a public channel
\end{itemize}

\subsubsection{Server: Write}
\begin{itemize}
    \item 

    \item Server state: message matrix $L$ of $\eta\times3$ slots, initialized to $\rlwe(0)$; availability matrix $I$ of $\eta\times3$ encryptions of $1$ --- $\eta$ buckets of $3$ slots, $3\eta$ slots total
    \item \textsc{HomExpand}: received bit encryptions are expanded \gls{rlwe} $\to$ \gls{rgsw}~\cite{chillotti:onionring:2019, park:sortinghat:2022}, so clients only ever upload \gls{rlwe} material (bandwidth optimization)
    \item \textsc{HomPlacing} (\autoref{alg:expandRlwe}, adapted from~\cite{park:sortinghat:2022}): a binary multiplexer tree of depth $\log\eta$ routes an encrypted value to the leaf addressed by the encrypted bits; $\mathcal{O}(\eta)$ homomorphic products per message
    \item Choice-of-three variant (\autoref{alg:spar:homplacing}): one tree per index $a_d$ produces indicator vectors $z_{i,d}$; the write loop then places $V_r = c_i$ into the first free slot among the three chosen buckets, tracked by the encrypted flags $h$ and $\mathsf{hasWritten}$
    \item Every homomorphic product is instantiated with the external product (\autoref{def:prod:external}) --- the practicality claim rests on this choice
    \item Collision analysis (balls and bins with $d$ choices): max bucket load $\log\log\eta/\log d + \mathcal{O}(1)$; for $d = 3$ the overflow probability is $< 10^{-11}$ with only $3\eta$ slots %% TODO bib: Mitzenmacher, "The power of two choices in randomized load balancing", 2001
    \item On the (negligible) overflow event the message is silently dropped; the client retransmits in a later round without degrading anonymity
    \item After all $\eta$ writes: obliviously sort each bucket ($3$ elements, independent buckets, parallelizable) --- required by \autoref{sec:spar:anonymity} %% TODO bib: Cong et al. (SAC 2024 top-k) + Azogagh et al. (eprint 2024/1894) for the sorting cost
    \item Broadcast all of $L$ to the clients
\end{itemize}

\subsubsection{Client: Partial Decryption}
\begin{itemize}
    \item Each client partially decrypts every slot of the broadcast $L$ with its share $s_i$, adding flooding noise (\autoref{sec:mpfhe}); the result $d_i$ is a vector of $3\eta$ \gls{rlwe} ciphertexts sent back to the server
    \item Total partial-decryption traffic is $\mathcal{O}(\eta^2)$ ciphertexts per round
    \item Packing optimization: LWE-to-RLWE conversion packs a client's partial decryptions into a single ciphertext when $N > 3\eta$, reducing traffic to $\mathcal{O}(\eta^2/N)$ %% TODO bib: Chen--Dai--Kim--Song, "Efficient homomorphic conversion between (R)LWE ciphertexts", 2021
\end{itemize}

\subsubsection{Server: Final Decryption}
\begin{itemize}
    \item Server aggregates the $\eta$ partial decryptions per slot and recovers the plaintext list (\autoref{sec:mpfhe})
    \item Empty slots decrypt to $0$ and are discarded; the surviving order is a fresh uniform permutation of the $\eta$ messages
    \item Broadcast: plaintexts in the sender-anonymous version; classically-encrypted inner ciphertexts in the recipient-anonymous version
\end{itemize}
