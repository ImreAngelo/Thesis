\label{sec:rgsw}

The GSW ciphertext defined in \cite{cryptoeprint:2013/340}, now in the ring $R_q$. It works by changing bases. Given a base $B$ and decomposition parameter \paramDecomp, such that the message $\mu$ can be expressed with $\ell$ digits in base $B$, define the \emph{gadget vector} as $g = (1, B, \dots, B^{\ell - 1})^\intercal\bmod{t}$ and define the \emph{gadget matrix} $G$ as \eqref{eq:gadget-matrix}.

\begin{equation}
    \label{eq:gadget-matrix}
    G = I_2 \otimes g =
    \begin{bmatrix}
        g & 0 \\
        0 & g
    \end{bmatrix}
\end{equation}

Then an \gls{rgsw} ciphertext $C$ encrypting a message $\mu \in [0, N)$ is defined by \eqref{eq:rgsw}, where each row of $Z$ is an \gls{rlwe} encryption of 0 under the secret key $s$ (effectively rows of public keys), $\mu$ is the message and $G$ is the gadget matrix.

\begin{equation}
    \label{eq:rgsw}
    C = Z + \mu \cdot G
\end{equation}

\noindent\textcolor{red}{\textbf{Notation: We use $\mathsf{RLWE}_s(\mu) = (a, b)$ throughout, where $b = a\cdot s + \mu + \epsilon$ (since $\Delta = 1$ in BGV). OpenFHE internally uses the order $(b, a)$ — this affects only the layout, not the math.}}

While \eqref{eq:rgsw} is sufficient to construct $\rgsw{\mu}$, we can speed up the process by directly encrypting each row. Note \gls{rgsw} can be viewed as a flat vector of $2\ell$ \gls{rlwe} ciphertexts where the first $\ell$ modify $a$ (we call these the \emph{top} rows) and the last $\ell$ modify $b$ (the \emph{bot} rows).

\begin{corollary}
\label{corollary:rgsw:bottom}
For an \gls{rgsw} ciphertext $C$ encrypting a message $\mu$ under $s$, the $(\ell + i)$-th row $(0 \leq i < \ell)$ is equivalent to:
\begin{equation}
    C_{\ell + i} = \rlwe{\mu B^i / \Delta}
\end{equation}

\begin{proof}
    Follows from the definitions \eqref{eq:rgsw} and \eqref{eq:gadget-matrix}.
    \begin{align*}
        Z_i + \mu\cdot G_i &= \rlwe{0} + \mu \cdot(0, g_i) \\
            &= (a, a\cdot s + \epsilon) + (0, \mu\cdot B^i) \\
            &= (a, a\cdot s + \mu B^i + \epsilon) \\
            &= \rlwe{\mu B^i/\Delta}
    \end{align*}
\end{proof}
\end{corollary}

\noindent The same approach shows the first $\ell$ rows can be constructed as an \gls{rlwe} encryption $c_i = \rlwe{-s\mu B^i/\Delta}$ for $0 \leq i <\ell$ (\autoref{lemma:rgsw:top}). However, calculating $s\cdot \mu$ is not trivial in practice, and it's faster to simply modify the $a$ component of a fresh $\rlwe{0}$ encryption. \autoref{alg:rgsw} creates $\rgsw{\mu}$ in $\mathcal{O}(\ell)$ steps (but can only be performed on the client-side as it requires $s$).

\subsection{Parameter Choice}
\label{sec:rgsw:params}

The choice of basis $B$ and decomposition parameter $\ell$ is one and the same. For a given basis, the message polynomial $\mu$ is rewritten into $\log_B(\mu)$ base-$B$ digits. Therefore $\ell \geq \log_B(\mu)$ (otherwise the RGSW does not encode all the digits) and $\ell \leq \log_B(\mu)$ (otherwise more $B$-digits would always be 0). The value of $\ell$ is squeezed and must equal the number of base-$B$ digits that encodes all $\mu$ values allowed by the scheme.

For BGV-RNS with $q = \prod_{i=0}^{k-1} q_i$ and 60-bit primes $q_i$, this gives $\ell = \lceil \log_B q \rceil = \sum_i \lceil \log_B q_i \rceil$. Even with a large base such as $B = 2^{30}$, $\ell$ is on the order of $2k$, growing linearly with the multiplicative depth.

\subsection{External Product (textbook)}
\label{sec:rgsw:extprod}

\ifnotes
\textcolor{magenta}{The purpose of using RGSW is to get ``access'' to the external product, which allows homomorphic multiplication without the expensive relinearization step.}
\fi

First defined in \cite{cryptoeprint:2018/421}. The external product \eqref{eq:externalprod} is defined between an \gls{rlwe} and a \gls{rgsw} ciphertext, and outputs an \gls{rlwe} ciphertext without using homomorphic multiplication (and thus relinearization). The external product uses a \emph{decomposition matrix} $G^{-1}$ that has the \emph{gadget property} \eqref{eq:gadget-property}, which effectively ``undoes'' the effect of the gadget matrix $G$ (with some error $\leq B/2$, assuming $x$ has binary elements).

\begin{align}
    \label{eq:gadget-property}
    G^{-1}(x)\cdot G &= x + e \pmod{q} \\
    \label{eq:externalprod}
    x \boxdot Y &= G^{-1}(x)\cdot Y
\end{align}

Correctness follows by linearity: writing $Y = \rgsw{\mu_y} = Z + \mu_y G$ and $x = \rlwe{\mu_x} = (a, as + \mu_x + \epsilon')$,
\begin{align}
    x \boxdot Y &= G^{-1}(x) \cdot (Z + \mu_y G) \\
                &= \underbrace{G^{-1}(x) \cdot Z}_{\text{small noise}} \;+\; \mu_y \cdot G^{-1}(x) \cdot G \\
                &\approx \mu_y \cdot x = \rlwe{\mu_x \mu_y} \pmod{q}.
\end{align}

\subsection{Internal Product (textbook)}
\label{sec:rgsw:intprod}

The \emph{internal product} \eqref{eq:intprod} multiplies two RGSW ciphertexts, producing a third RGSW ciphertext. Each row of $B$ is itself an RLWE ciphertext (\autoref{corollary:rgsw:bottom}), so the internal product is $2\ell$ external products, one per row, repacked as an RGSW.

\begin{equation}
    \label{eq:intprod}
    A \boxtimes B =
    \begin{bmatrix}
        A \boxdot b_0 \\
        A \boxdot b_1 \\
        \vdots \\
        A \boxdot b_{2\ell - 1}
    \end{bmatrix}
\end{equation}

The cost is therefore $\mathcal{O}(\ell)$ external products, or $\mathcal{O}(\ell^2)$ total ring multiplications.

\subsection{The Hybrid-Keyswitch RNS Gadget}
\label{sec:rgsw:hybrid}

The textbook gadget $g = (1, B, \dots, B^{\ell-1})$ from \autoref{sec:rgsw:params} pays a steep price in BGV-RNS: $\ell \approx 2k$ rows, each a full \gls{rlwe} ciphertext. The \emph{hybrid keyswitch} construction (used by OpenFHE for relinearization) replaces this with an RNS-native gadget of length $\dnum$ where typically $\dnum \in \{2, 3, 4\}$, independent of $B$. We adapt it to RGSW.

The idea: instead of decomposing each coefficient into base-$B$ digits, we decompose the \emph{tower index} $i$ into a small number of partitions, and use the QP-basis identity from \autoref{lem:P-cancel} to cancel the gadget factor.

\subsubsection{Q-partitions}

Partition the $k$ RNS towers of $Q$ into $\dnum$ contiguous groups of $\alpha = \lceil k / \dnum \rceil$ towers each (the last group may be shorter):
\begin{equation}
    \label{eq:partitions}
    \mathsf{part}_j = \{ i \in [0, k) : j \alpha \leq i < (j+1)\alpha \}, \qquad j \in [0, \dnum).
\end{equation}
Let $Q_j = \prod_{i \in \mathsf{part}_j} q_i$ so that $Q = \prod_{j=0}^{\dnum - 1} Q_j$. In OpenFHE, $\dnum$ is set via \texttt{CCParams::SetNumLargeDigits}, and $\alpha$ is exposed as \texttt{numPerPartQ}.

\subsubsection{The partition-indicator gadget element}

For each partition $j$, define the QP-element $g_j \in R_{QP}$ tower-by-tower:
\begin{equation}
    \label{eq:gj}
    g_j[i] =
    \begin{cases}
        [P]_{q_i} \pmod{q_i} & i \in \mathsf{part}_j \quad (Q\text{-side}) \\
        0                    & i \in [0, k) \setminus \mathsf{part}_j \quad (Q\text{-side}) \\
        0                    & i \in P\text{-side}
    \end{cases}
\end{equation}

That is: $g_j$ is the QP element holding the value $[P]_{q_i}$ in those $Q$-towers that belong to partition $j$, and zero everywhere else. The constants $[P]_{q_i}$ are precomputed in OpenFHE as \texttt{cryptoParams->GetPModq()}.

\begin{remark}
The textbook gadget $g_i = B^i$ used a single integer per row; the hybrid gadget $g_j$ uses an entire QP-element per row, but the element is sparse (zero outside one Q-partition) and its non-zero entries are determined by the auxiliary modulus $P$.
\end{remark}

\subsubsection{Digit decomposition}

Given $c \in R_Q$, define the $j$-th digit $\mathsf{Decomp}_j(c) \in R_{QP}$ as the basis-extension of $c$'s partition-$j$ slice into all of $QP$. Concretely, take the residues $\{ c \bmod q_i : i \in \mathsf{part}_j \}$ as a polynomial in $R_{Q_j}$, then \textsf{ApproxSwitchCRTBasis} from $Q_j$ to $QP$. This gives a vector of $\dnum$ elements in $R_{QP}$, one per partition.

In OpenFHE this routine is \texttt{KeySwitchHYBRID::EvalKeySwitchPrecomputeCore}.

\begin{lemma}[Gadget identity]
\label{lem:gadget-identity}
For any $c \in R_Q$,
\begin{equation}
    \label{eq:gadget-identity}
    \sum_{j=0}^{\dnum-1} \mathsf{Decomp}_j(c) \cdot g_j \;\equiv\; P \cdot c \pmod{Q},
    \qquad \equiv\; 0 \pmod{P}.
\end{equation}
\end{lemma}

\begin{proof}
Examine each tower of $QP$ separately.

\noindent\emph{Q-side, tower $i \in \mathsf{part}_j$:} For the partition $j' = j$ that contains $i$, $\mathsf{Decomp}_j(c)[i] = c[i]$ exactly --- the partition-$j$ slice contains tower $i$ natively, no basis extension needed. And $g_j[i] = [P]_{q_i}$, so the contribution is $c[i] \cdot [P]_{q_i} \equiv P \cdot c[i] \pmod{q_i}$. For all other partitions $j' \neq j$, $g_{j'}[i] = 0$, contributing nothing. Total: $P \cdot c[i] \pmod{q_i}$.

\noindent\emph{P-side, tower $i$:} $g_j[i] = 0$ for all $j$, so the sum is $0$.
\end{proof}

Compare \eqref{eq:gadget-identity} with the textbook $\sum_i u_i \cdot B^i = c$: the two play the same role, but the hybrid form picks up a free factor of $P$ on the $Q$-side that we will cancel with \textsf{ApproxModDown} (\autoref{lem:P-cancel}).

\subsubsection{V2 RGSW format}
\label{sec:rgsw:v2-format}

Define $\rgsw{m}$ as two arrays of $\dnum$ pairs in $R_{QP}^2$ each:
\begin{align}
    \label{eq:rgsw-v2-top}
    b_j^{\mathsf{top}} + a_j^{\mathsf{top}} \cdot s &\;\approx\; m \cdot s \cdot P \cdot g_j \pmod{QP} \\
    \label{eq:rgsw-v2-bot}
    b_j^{\mathsf{bot}} + a_j^{\mathsf{bot}} \cdot s &\;\approx\; m \cdot P \cdot g_j \pmod{QP}
\end{align}
for $j \in [0, \dnum)$. The factor $P$ on the right-hand side comes from $g_j$ (whose non-zero entries are $[P]_{q_i}$); we factor it out as a separate $P$ for clarity in the derivations below. This is implemented in \texttt{EncryptRGSW} (\autoref{alg:rgsw-v2}).

%% V2 RGSW encryption algorithm
\begin{algorithm}[ht!]
\caption{V2 \gls{rgsw} encryption (server-side, mirrors hybrid keyswitch)}
\label{alg:rgsw-v2}
\begin{algorithmic}[1]
    \State \textbf{Input:} secret key $s \in R_Q$; message $m \in R_t$; partition count $\dnum$
    \State \textbf{Output:} $\rgsw{m}$ in V2 format
    \State Encode $m \in R_t$ as $m_Q \in R_Q$, then extend $s \to s_{QP} \in R_{QP}$
    \For{$j = 0,\dots,\dnum - 1$}
        \For{$\mathsf{side} \in \{\mathsf{top}, \mathsf{bot}\}$}
            \State Sample $a \leftarrow U(R_{QP})$ and $e \leftarrow \mathsf{DGG}(R_{QP})$
            \State Let $\mathsf{payload}_Q = m_Q \cdot s$ (top) or $m_Q$ (bot)
            \For{tower $i \in [0, \mathsf{sizeQ} + \mathsf{sizeP})$}
                \If{$i \in \mathsf{part}_j$ (Q-side)}
                    \State $b[i] \gets -a[i] \cdot s_{QP}[i] + e[i] + [P]_{q_i} \cdot \mathsf{payload}_Q[i]$
                \Else
                    \State $b[i] \gets -a[i] \cdot s_{QP}[i] + e[i]$
                \EndIf
            \EndFor
            \State Store $(a, b)$ as $(a_j^{\mathsf{side}}, b_j^{\mathsf{side}})$
        \EndFor
    \EndFor
    \State \Return $\{(a_j^{\mathsf{top}}, b_j^{\mathsf{top}}), (a_j^{\mathsf{bot}}, b_j^{\mathsf{bot}})\}_{j=0}^{\dnum - 1}$
\end{algorithmic}
\end{algorithm}

The structure mirrors \texttt{KeySwitchHYBRID::KeySwitchGenInternal} exactly, with the message $m$ playing the role of the ``old'' secret key in the keyswitch.

\subsubsection{V2 External product, derived}
\label{sec:rgsw:v2-extprod}

Given an RLWE ciphertext $x = (a_x, b_x) \in R_Q^2$ encrypting $m_x$ (so $b_x + a_x s \approx m_x \pmod{q}$) and an RGSW ciphertext $Y = \rgsw{m_y}$ in V2 format, compute:

\begin{enumerate}
    \item $\mathsf{vDig}[j] = \mathsf{Decomp}_j(b_x), \quad \mathsf{uDig}[j] = \mathsf{Decomp}_j(a_x)$ for $j \in [0, \dnum)$.
    \item Inner products in $R_{QP}$:
    \begin{align}
        r_0 &= \sum_j \mathsf{uDig}[j] \cdot b_j^{\mathsf{top}} + \mathsf{vDig}[j] \cdot b_j^{\mathsf{bot}} \\
        r_1 &= \sum_j \mathsf{uDig}[j] \cdot a_j^{\mathsf{top}} + \mathsf{vDig}[j] \cdot a_j^{\mathsf{bot}}
    \end{align}
    \item Output $(\mathsf{ApproxModDown}(r_1), \mathsf{ApproxModDown}(r_0)) \in R_Q^2$.
\end{enumerate}

\begin{lemma}[V2 external product correctness]
\label{lem:v2-extprod}
$\mathsf{ApproxModDown}(r_0) + \mathsf{ApproxModDown}(r_1) \cdot s \approx m_x \cdot m_y \pmod q$.
\end{lemma}

\begin{proof}
Compute $r_0 + r_1 \cdot s$ in $R_{QP}$ using \eqref{eq:rgsw-v2-top}--\eqref{eq:rgsw-v2-bot}:
\begin{align}
    r_0 + r_1 s &= \sum_j \mathsf{uDig}[j] \cdot \big(b_j^{\mathsf{top}} + a_j^{\mathsf{top}} s\big) + \mathsf{vDig}[j] \cdot \big(b_j^{\mathsf{bot}} + a_j^{\mathsf{bot}} s\big) \\
                &\approx \sum_j \mathsf{uDig}[j] \cdot m_y \cdot s \cdot P \cdot g_j + \sum_j \mathsf{vDig}[j] \cdot m_y \cdot P \cdot g_j \\
                &= m_y \cdot s \cdot P \cdot \underbrace{\sum_j \mathsf{uDig}[j] \cdot g_j}_{\equiv P \cdot a_x} \;+\; m_y \cdot P \cdot \underbrace{\sum_j \mathsf{vDig}[j] \cdot g_j}_{\equiv P \cdot b_x} \tag{by \autoref{lem:gadget-identity}} \\
                &\equiv m_y \cdot P^2 \cdot (a_x s + b_x) \pmod{Q} \\
                &\approx m_y \cdot P^2 \cdot m_x \pmod{Q}.
\end{align}
On the $P$-side, both gadget sums are $0$ (\autoref{lem:gadget-identity}), so $r_0 + r_1 s \equiv 0 \pmod{P}$. Applying \autoref{lem:P-cancel} to $\mathsf{ApproxModDown}$:
\begin{equation}
    \mathsf{ApproxModDown}(r_0) + \mathsf{ApproxModDown}(r_1) \cdot s \approx \frac{m_y \cdot P^2 \cdot m_x}{P} = m_y \cdot P \cdot m_x \cdot \frac{1}{P} \equiv m_x m_y \pmod q,
\end{equation}
since the second \textsf{ApproxModDown} application strips the remaining $P$ factor.
\end{proof}

\noindent\textcolor{magenta}{\textbf{Implementation note.} \autoref{lem:v2-extprod} corresponds line-by-line to \texttt{EvalExternalProduct} in \texttt{src/core/context.cpp}. Step 1 is \texttt{EvalKeySwitchPrecomputeCore} (lines 99--101), step 2 is the inner loop (lines 114--129), step 3 is \texttt{ApproxModDownToQ} (lines 132--133). The total cost is \emph{2 ModUps + $2\dnum \cdot \mathsf{sizeQP}$ pointwise multiplies + 2 ApproxModDowns} --- versus $2\ell \approx 4k$ full RLWE rows in the textbook version.}

\subsubsection{V2 Internal product, derived}
\label{sec:rgsw:v2-intprod}

For each row $(a_j^{\mathsf{side}}, b_j^{\mathsf{side}})$ of $B = \rgsw{m_B}$, observe that it is an RLWE-shaped pair in $R_{QP}$ encrypting $m_B \cdot P \cdot g_j$ (or $m_B \cdot s \cdot P \cdot g_j$ for top rows). To produce the corresponding row of $\rgsw{m_A m_B}$, we apply the external product action of $A$ and re-fit into the V2 format:

\begin{enumerate}
    \item Project the row from $R_{QP}$ to $R_Q$ via \textsf{ApproxModDown}, cancelling the gadget's $P$ factor (\autoref{lem:P-cancel}). The result is an RLWE ciphertext in $R_Q$ encrypting $m_B \cdot g_j$ (bot) or $m_B \cdot g_j \cdot s$ (top), where $g_j$ is interpreted as the $Q$-only indicator (value $1$ on partition $j$, $0$ elsewhere).
    \item Apply the V2 external product of $A$ to this row. The result is an RLWE ciphertext in $R_Q$ encrypting $m_A \cdot m_B \cdot g_j$ (or with an extra $\cdot s$ for top).
    \item Lift back to $R_{QP}$ by multiplying each $Q$-tower by $[P]_{q_i}$ and zeroing the $P$-side. This restores the V2 format \eqref{eq:rgsw-v2-top}--\eqref{eq:rgsw-v2-bot} with $m \mapsto m_A m_B$.
\end{enumerate}

This is implemented in \texttt{EvalInternalProduct} (\texttt{context.cpp:287--381}). The cost is $2\dnum$ external products plus the round-trip overhead, i.e.\ $\mathcal{O}(\dnum^2)$ ring multiplications --- versus the textbook $\mathcal{O}(\ell^2) \approx \mathcal{O}(k^2)$.

\subsubsection{Per-level alignment}
\label{sec:rgsw:level-align}

When $x$ has been mod-reduced to $Q_\ell \subset Q$ (some subset of the towers), the digit decomposition automatically returns fewer digits ($\mathsf{numPartQ_\ell} \leq \dnum$), and the inner loop indexes into the full-$Q$ RGSW with offset $\delta = \mathsf{sizeQ} - \mathsf{sizeQ_\ell}$ to skip dropped towers. This is the same trick OpenFHE's \texttt{EvalFastKeySwitchCoreExt} uses, and gives mod-reduced $x \boxdot Y$ for free without re-encrypting the RGSW at each level.

The novel angle: in V2 the gadget identity \eqref{eq:gadget-identity} carries an extra factor of $P$, exactly the auxiliary modulus that \textsf{ApproxModDown} cancels. The external product therefore fuses three operations into a single coherent pass: digit decomposition (ModUp), inner product against the gadget rows, and removal of the auxiliary modulus (ModDown) --- the same machinery as relinearization, with $\dnum$ as the single shared parameter (\texttt{SetNumLargeDigits}).

\subsection{RLWE-to-RGSW Expansion from ORAM}
\ifnotes
\begin{itemize}
    \item We want to use RGSW to avoid relinearization
    \item We want to send packed ciphertexts to save on communication
    \item Therefore, we send RLWE and convert to RGSW on the server
    \item (Requires a single RGSW encryption $\mathsf{RGSW}(-s)$ to be sent as well)
    \item 1 RLWE for the index bits = size $\ell$
    \item $\ell$ RGSW's for the index bits = size $2\ell \times 2$ or smth
    \item Expanding = size $2\ell$ or something
\end{itemize}
\fi
As established in \autoref{sec:rgsw}, \gls{rgsw} ciphertexts are enticing because the external product allows us to perform homomorphic multiplication without relinearization. However, the size of \gls{rgsw} makes the communication costs very high in a communication protocol. We wish to strike a balance between the cheap communication cost of packed \gls{rlwe} and the fast multiplication of \gls{rgsw}. The solution is to send \gls{rlwe} ciphertexts from the client, and \emph{expand} them homomorphically on the server.

Solution from \autocite{chillotti:onionring:2019}. \textbf{HomExpand:} Expands an \gls{rlwe} ciphertext into an \gls{rgsw} ciphertext.

This expansion is described in Algorithm 4 of \cite{chillotti:onionring:2019}, which builds on Algorithms 3 and 8 from the same paper. The algorithms are listed below (in slightly different notation) as \autoref{alg:ORAM:4}, \autoref{alg:ORAM:3}, and \autoref{alg:ORAM:8}, respectively.
