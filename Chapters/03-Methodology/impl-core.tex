\section{Implementation Details of the Core Library}
\label{sec:impl:core}
The core library, located in the \texttt{lib/core} directory of \cite{gitrepo} provides an abstract interface named \texttt{ExtendendedCryptoContext} which provides a number of RGSW functions, including RGSW encryption, external product and internal product. % The most important of which are \texttt{EncryptRGSW}, \texttt{EvalExternalProduct} and \texttt{EvalInternalProduct}
Any project that requires this functionality can import the library and consume this interface without worrying about the implementation of the interface. The library is built on top of OpenFHE~\cite{cryptoeprint:2022/915} and the interface reflects that, mirroring the API of OpenFHE. A user who is familiar with OpenFHE should as a result have no problem using this library in their own projects.

\begin{table}[H]
    \centering
    \label{tab:main-functions}
    \caption{Primary functionality provided by \texttt{ExtendedCryptoContext}}
    \begin{tabular}{r|l}
        \Call{EncryptRGSW}{pk, pt}              & Outputs an RGSW ciphertext \\
        \Call{EvalExternalProduct}{rlwe, rgsw}  & Outputs the external product \\
        \Call{EvalInternalProduct}{lhs, rhs}    & Outputs the internal product
    \end{tabular}
\end{table}

The \texttt{ExtendedCryptoContext} interface comes bundled with two concrete implementations. One is designed around gadget decomposition of the RNS primes as described in \autoref{sec:gadget-decomposition}, and will be referred to as the BV implementation. The other implementation is designed around the hybrid keyswitching mechanism from \autoref{sec:hybrid}. Of these, the former should be considered the ``canonical'' implementation because (1) this design is the most closely related to the external product as discussed in the literature, where this product is traditionally defined using digit decomposition \cite{examples-of-this, cryptoeprint:2025/860}, and (2) the other implementation does not use true \gls{rgsw} ciphertexts.

\begin{remark}
    \color{red}
    The implementations are hard coupled to the BGV-RNS (\texttt{CryptoContextBGVRNS}) scheme. As OpenFHE provides a unified interface for both BGV and BFV --- and the TFHE products are defined independent of scheme --- it would not require much work to add support for BFV to the core library.
\end{remark}
