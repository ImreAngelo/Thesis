\section{Implementation Details of the Core Library}
\label{sec:impl:core}
The core library, located in the \texttt{libs/core} directory of the repository \cite{gitrepo}, extends OpenFHE~\cite{cryptoeprint:2022/915} with \gls{rgsw} functionality that the framework does not itself expose; of which the most important functions are listed in \autoref{tab:main-functions}. These are declared by an abstract interface, \texttt{IExtendedContext}, allowing alternative implementations to serve as drop-in replacements without requiring user modifications in the future. We also provide a concrete implementation using gadget decomposition of the RNS moduli, as described in \autoref{sec:gadget-decomposition}. Following the convention of~\cite{cryptoeprint:2021/204, cryptoeprint:2022/915}, we use \emph{BV} to refer to this technique, after Brakerski and Vaikuntanathan~\cite{cryptoeprint:2011/344}, and by extension to the implementation built on it.

%%
%% OpenFHE API
The core library is designed to seamlessly extend OpenFHE, with the aim of making it easy for developers already familiar with OpenFHE to include and use in their own projects. Specifically, OpenFHE works by initializing a \emph{cryptographic context} that holds static parameters, such as the RNS moduli $q_i$. All homomorphic operations are called through the context object. Our library preserves this pattern: the functions of \autoref{tab:main-functions} are methods on the same context object and operate directly on OpenFHE's native ciphertext types, so standard and extended operations can be freely interleaved.

\begin{example}[Simple Library Usage] 
\begin{minted}{c++}

// Using standard OpenFHE functions 
auto ct = cc->Encrypt(publicKey, m);
auto ct_sqr = cc->EvalMult(ct, ct); // Result is RLWE(m*m)

// Using functions provided by the IExtendedContext interface
auto rgsw_one = cc->EncryptRGSW(publicKey, m); // RGSW(m)
auto ct_ext = cc->EvalExternalProduct(ct, rgsw_one); // RLWE(m*m)
\end{minted}
\end{example}
