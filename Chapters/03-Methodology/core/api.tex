\section{Implementation Details of the Core Library}
\label{sec:impl:core}
The core library, located in the \texttt{libs/core} directory, extends OpenFHE~\cite{cryptoeprint:2022/915} with \gls{rgsw} functionality that the framework does not itself expose; of which the most important functions are listed in \autoref{tab:main-functions}. These are declared by an abstract interface, \texttt{IExtendedContext}, allowing alternative implementations to serve as drop-in replacements without requiring user modifications in the future. % This allows different gadgets to be utilized without inconveniencing the project...
We also provide a concrete implementation using gadget decomposition of the RNS moduli, as described in \autoref{sec:gadget-decomposition}. Following the convention of~\cite{cryptoeprint:2021/204, cryptoeprint:2022/915}, we use \emph{BV} to refer to this technique after Brakerski and Vaikuntanathan's work in~\cite{cryptoeprint:2011/344}.

%%
%% OpenFHE API
The core library is designed to seamlessly extend OpenFHE, aiming to make the library easy to use for developers already familiar with OpenFHE in their own projects. Specifically, OpenFHE works by initializing a \emph{cryptographic context} that holds static parameters, such as the RNS moduli $q_i$. All homomorphic operations are called through the context object. This pattern is preserved in our library: the functions of \autoref{tab:main-functions} are methods on the same context object and operate directly on OpenFHE's native ciphertext types.

\begin{example}[Simple Library Usage] 
\begin{minted}{c++}


// Using standard OpenFHE functions 
auto ct = cc->Encrypt(publicKey, m);
auto ct_sqr = cc->EvalMult(ct, ct); // Result is RLWE(m*m)

// Using functions provided by the IExtendedContext interface
auto rgsw = cc->EncryptRGSW(publicKey, m); // RGSW(m)
auto ct_ext = cc->EvalExternalProduct(ct, rgsw); // RLWE(m*m)
\end{minted}
\end{example}
