\section{Parameters}
\label{sec:results:params}
We found that the parameters suggested in \cite{cryptoeprint:2025/860} results in too much noise for the \texttt{Server::Write} function to effectively handle, and are thus not capable of running the full \gls{spar} protocol without decryption failure. Rather than tweaking these parameters until the protocol produces correct decryptions, we instead aim to fully utilize the \gls{rns} context by using much large parameters that enable \gls{simd} batching and far more data transferred per message.

New parameters were thus selected to provide $\lambda \geq 128$ bits of security at the largest possible modulus $Q$, while supporting \gls{simd} batching, minimizing $k\ell$, and ensuring sPAR outputs correct results. The RNS moduli are slightly smaller than $64$ bits to fit inside $64$-bit machine words with a few bits of headroom to prevent overflowing registers.

The resulting parameters, listed in~\autoref{tab:bench:params}, yield an esitmated security parameter of $\securityBits$ bits~\cite{cryptoeprint:2015/046} for the underlying \gls{rlwe} scheme, and serve as the baseline for the benchmarks that follow.
