\section{Parameters}
I found that the parameters suggested in \cite{cryptoeprint:2025/860} results in too much noise for the \texttt{Server::Write} function to effectively handle, and are thus not capable of running the full \gls{spar} protocol without decryption failure. Rather than tweaking these parameters until the protocol produces correct decryptions, I instead aim to fully utilize the \gls{rns} context by using much larger parameters that enable \gls{simd} batching and far more data transferred per message. % The parameteres were designed for TFHE, with Q = 2^64

New parameters were thus selected to provide $\lambda \geq 128$ bits of security at the largest possible modulus $Q$, while supporting \gls{simd} batching, minimizing $\ell$ so that $k\ell$ is as small as possible, and ensuring sPAR outputs correct results. The RNS primes are slightly smaller than $64$ bits to fit inside $64$-bit machine words with a few bits of headroom to prevent overflowing registers. %% TODO: Explain breifly why first prime is slightly larger, and maybe alter scaling mod size so they are smaller?

The resulting parameters, listed in~\autoref{tab:bench:params}, yield an esitmated security parameter of $\securityBits$ bits~\cite{cryptoeprint:2015/046} for the underlying \gls{rlwe} scheme, and serve as a baseline for the benchmarks that follow. In some cases, varying some parameter, for example $\ell$, is of interest. In this case, deviations from the base parameters will be explicitly listed.

    \begin{tabular}{lcc}

        \bottomrule
    \end{tabular}
\end{table}

Note that the RNS moduli $q_i$ are randomly generated $59$-bit primes to guarantuee the moduli are pairwise coprime so \gls{crt} can be applied.
