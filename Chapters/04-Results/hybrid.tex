\subsection{Theoretical Hybrid Improvement}
\label{sec:results:hybrid}
An alternative to gadget decomposition often employed in \gls{rns} key-switching is the \textit{hybrid} technique \cite{cryptoeprint:2012/099, cryptoeprint:2021/204}. A natural question is wether this technique can be employed in the external and internal products.

% We defer a proper treatise of the 
In hybrid, the idea is to pre-scale a message $m$ by an auxiliary modulus $P$, where $|P| \approx |Q|/d_{num}$ for some integer $d_{num} \;|\; k$, resulting in a encryption of $m\cdot P$ in the extended ciphertext modulus $QP$. After some homomorphic operation(s) we end up with the message $m'P$ and noise $\epsilon' \geq\epsilon$. Dividing the ciphertext by $P$ will result in a ciphertext encrypting $m'$ in modulus $Q$, scaling down the error by $P$ in the process.
\begin{gather*}
    (a\cdot s + \Delta m P + \epsilon, a) \pmod{QP} \\
    P^{-1}\cdot \left[(a\cdot s + \Delta m' P + \epsilon', a) \pmod{QP}\right] \\
    (a'\cdot s + \Delta m' + \epsilon'/P, a') \pmod{Q}
\end{gather*}

Reframing this technique in terms of the gadget framework established in \autoref{sec:gadget-decomposition} is straight forward. If we let $g = P$, the gadget property holds in the extended modulus $QP$. Using $P^{-1}$ as our decomposition is identical to dividing by $P$ in hybrid.
\begin{gather*}
    \langle x, yP\rangle = x\cdot y \cdot P \pmod{QP} \\
    \langle P^{-1}\cdot x, yP\rangle = P^{-1}\left[\langle x, yP\rangle\right] = x\cdot y \pmod{Q}
\end{gather*}

This is sufficient to define the external product using the hybrid gadget.\footnote{This should come as no surprise since key-switching and the external product is essentially the same operation.} We must note, however, that this creates an imbalance between the left and right operands, where the right \gls{rgsw} has rows in the extended $QP$-modulus space while the left \gls{rlwe} is defined in the target modulus $Q$.

\begin{definition}[Hybrid-RGSW]
    An \gls{rgsw} ciphertext that encodes $\mu P$ \textbf{in the extended modulus} $QP$.
    \begin{equation}
        \label{eq:hybrid-rgsw}
        C_{QP} = Z_{QP} + \mu \begin{pmatrix}
            P & 0 \\
            0 & P
        \end{pmatrix} \pmod{QP}
    \end{equation}
    % \begin{equation}
    %     \Call{HybridRGSW}{b} = \Call{RGSW}{b\cdot P}
    % \end{equation}
\end{definition}

Thanks to the abstract interface layout of the core library, a second implementation was developed for this thesis that implements the external product. Note that this implementation is technically using the \emph{GHS} technique from~\cite{cryptoeprint:2012/099}, which is (by definition) hybrid with $d_{num} = 1$. % The implementation was tested in the same way, with the same parameters, as the BV implementation.

\subsubsection{Internal Product}
One would think that since the internal product is defined as repeated applications of the external product, the hybrid technique would extend to this product as well. It does not. The noise advantage of the hybrid external product comes from the rescaling by $P^{-1}$, which necessarily maps the result down to modulus $Q$. Since $P$ is a zero divisor of the ring $R_{QP}$, the inverse does not exist and division by $P$ is only well-defined as a map $R_{QP}\to R_{Q}$. Therefore, a pure ``hybrid'' internal product cannot exist.

\subsubsection{A Compromise}
Observe that the pure hybrid internal product only breaks because we require the output to be in a modulus that is a factor of $P$. If we distinguish between a \emph{left} (regular) and a \emph{right} (hybrid) RGSW, then we can define a \textit{mixed} product that takes a hybrid-RGSW as one of its operands, but outputs a regular RGSW. Importantly, this product would be infinitely chain-able using only hybrid external products.

\newcommand{\mixedprod}{\;\boxed{\diamond}\;}
\begin{corollary}[Mixed Product]
    Let $\boxdot$ denote the hybrid external product. Let $S$ be an \gls{rgsw} ciphertext \eqref{def:rgsw} with $2\ell$ rows and $H$ be a hybrid-RGSW ciphertext \eqref{eq:hybrid-rgsw}. We define the \emph{mixed internal product} $\mixedprod$ as
    \begin{align}
        \mixedprod:\;\; \Call{RGSW}{} \mixedprod \Call{HybridRGSW}{} &\longmapsto \Call{RGSW}{}  \\
        (A, H) &\longmapsto A \mixedprod H = \begin{bmatrix}
            A_0 \boxdot H \\
            \vdots \\
            A_{2\ell - 1} \boxdot H
        \end{bmatrix}
    \end{align}
    
    and propose that this product is \emph{right-chainable} wrt. hybrid-RGSW ciphertexts, in the sense that a sequence of hybrid-RGSW ciphertexts $H_i$ can be repeatedly applied as the right operand: 
    \begin{equation*}
        (((S \mixedprod H_0) \mixedprod H_1) ... ) \mixedprod H_i \mapsto \Call{RGSW}{}
    \end{equation*}
\end{corollary}

This product has not been implemented in our code, so we can only speculate on its performance. However, it stands to reason that it would outperform the regular internal product in an \gls{rns} setting as it uses the faster hybrid external product. In \gls{spar}, specifically, it can be applied to the \texttt{server::Write} loop by setting $h\gets (I_{i,k}\boxtimes \mathsf{notHasWritten}) \mixedprod z_{i,d}$ and having the client send $z$ pre-scaled by $P$ and in the $QP$-modulus space.

To summarize, we believe that if \autoref{alg:spar:write} was rewritten using only external products, the performance would be significantly improved by using the hybrid technique. Barring that, the protocol might also see a non-negligible speed-up by employing the mixed product when assigning $h$.
